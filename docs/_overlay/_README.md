# The docs overlay

`site_docs/` — what MkDocs actually builds — is generated by
`scripts/gen_docs.py` from two inputs:

1. `knowledge/`, the OKF bundle, transformed into plain Markdown
2. this directory, copied verbatim on top

Nothing in `site_docs/` is edited by hand; it is gitignored and rebuilt on every
`pixi run docs-build`.

## What belongs here

Anything the site needs that is not project knowledge: the landing page,
handwritten guides, images, stylesheets, downloads. Files of any type are
copied, at any depth, and a file here overrides a generated page at the same
path — which is how a concept page can be replaced by hand if it ever needs to
be.

## What does not

Concepts. If it is a decision, a constraint, or a property of the data, it
belongs in `knowledge/` and reaches the site automatically. Writing it here
instead puts it out of reach of `okf search`, which is what agents read.

## The underscore prefix

Files and directories starting with `_` are fragments, not pages: the generator
splices them into generated output instead of publishing them.
`<section>/_intro.md` is the paragraph that appears under a section's heading,
above its generated listing. This file is `_`-prefixed for the same reason.

## Nothing gets silently dropped

`mkdocs.yml` sets `validation.nav.omitted_files: warn`, and the build runs
`--strict`. A page that exists but never reaches the navigation fails the build
rather than quietly disappearing.
